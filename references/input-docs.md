# 需求文档导入（`--from=<path>`，F2-docs）

> 本文件由 SKILL.md 拆出（2026-10-27 F2-docs）。SKILL.md 只保留「怎么做 + 何时读」；要改解析规则/别名表/假设文案时读本文件。本文件不再链向其它 references 文件（引用只一层深）。

## 入口与硬失败

```
node <S>/scripts/generate-prd.js --from=<需求文档.md> [--dry-run]
```

- **只认等号式**：`--from <path>`（空格式）、`--from=`（空值）都是硬失败 —— 空格式会被当成「需求原话」，从而静默生成一份通用 PRD 覆盖用户的 `docs/prd.md`，这是最难排查的一类错。
- **不可与原话同给**：`--from=<path> "我想做一个…"` → exit 1（想用文档就只给 `--from`）。
- 路径基准 = **进程 cwd**（与 `--prd` 同口径，不用 `WORKSPACE`）——文档通常躺在调用方仓库里。
- 其余硬失败：文档不可读 / 为空 / **解析出 0 页** / 产物正文 < 500 字。全部 exit 1，**不回退默认 4 页页集**（回退会产出一份与文档无关的原型，比报错更难查）。

## 输入只吃 Markdown

纯文本、Word 不在本通道内；**截图/设计稿**先由 agent 按 `templates/design-spec.md` 整理成 Markdown（见文末「截图/设计稿」），再走同一条 `--from=`。文档至少要有一行 `# <产品名>`（否则下游 `validatePRD` 报「无法识别产品名称」）。

## 页面从哪来（唯一来源）

只扫**页面类小节**的列表项：`页面清单` / `页面列表` / `核心页面` / `页面` / `page list`（层级 2–3，容忍 `## 5. 页面清单与跳转关系`、`## 3.1 页面清单`、`## 一、页面` 这类序号前缀与后缀；围栏代码块内的 `#` 不算标题）。标题两侧都**带锚**：`## 页面标题规范` / `## 页面跳转关系` 这类不算页面小节（否则正文里的 `- 详情页禁止使用弹窗` 会被认成 detail 而静默增页）；`# 页面清单`（1 级）也不识别 —— 页面小节必须写在 2–3 级标题下。

**「功能 / 模块」小节永不参与页集推断** —— 否则「订单管理」「收藏夹」「扫码登录」会被 `includes` 命中，凭空多出页面。

每条列表项的处理顺序：`normalizePageName`（既有中文/英文页名映射）→ `PAGE_ALIASES`（业务词收敛）→ **统一过 `INTER_10` 闸门**。

## `INTER_10`：双端交集 10 页（唯一准入闸门）

`home / discover / list / detail / publish / chat / orders / profile / login / register`

`dashboard / settings / form` 是**桌面专属**模板，mobile 侧没有对应 `.eta`。文档导入在这里就把它们挡掉（记假设、不进页集）；**生成器侧另有兜底**：若页面清单（或 `--page`）仍把这类页带进页集，`buildOnce` 会按平台模板过滤——跳过该页、记入 `report.skippedPages`、并打一条 warn，**不再渲染 home 副本**。过滤后为空则 exit 1 并列出本平台可用页名。另：本路径页集受 `INTER_10`（10 页）约束，**结构上不会触发** 10 页上限截断（`report.truncatedPages` 恒为 `[]`）。

> 与 `--prd` 严格路径的分工：文档导入的未登记词进**假设清单**（`prd-assumptions.json`）；`--prd` 路径没有假设清单，改走 **warn + `report.unknownPages`**。若页面清单一条都识别不出，`parsePRD` 会回退默认 4 页，生成器必须 warn（产物与 PRD 无关，不能静默）。

## 别名表（只收敛、不新增页）

| 业务词 | 落点 |
|---|---|
| 购物车 / 购物袋 / 结算 / 收银台 | `orders` |
| 收藏 / 收藏夹 / 心愿单 | `profile` |
| 搜索 / 搜索页 | `discover` |
| 分类 / 分类页 | `list` |
| 地址 / 收货地址 | `profile` |
| 通知 / 消息中心 | `chat` |

- 别名**只在 tolerant（`--from`）分支生效**；默认 `parsePRD` 分支不吃别名（自检场景 39 ④b 是这条的永久断言）。
- 落点必须在 `INTER_10` 内；**页集只减不增**，不自动补模板、不提供 `--allow-new-page`。
- 匹配规则：整条命中优先，其次最长词包含（「购物车页」也能收敛）。

## 假设清单：`<WORKSPACE>/docs/prd-assumptions.json`

```json
{ "prdPath": "<绝对路径>/docs/prd.md", "prdSha1": "<PRD 正文 sha1>", "assumptions": ["[页面] …", "[章节] …"] }
```

- 由 `generate-prd.js` **独占写**，`--from` 成功分支**每次先删后写**（该文件是「上一次导入」的状态，残留会让下游把原话生成的 PRD 误标成文档来源）。
- 下游 `generate-prototype.js` 只读，且**双条件**才认：`resolve(json.prdPath) === resolve(本次 prdPath)` **且** `json.prdSha1 === sha1(本次 PRD 正文)`。任一不符 → 按「无假设」处理（`prdSource: 'prd'`、`assumptions: []`）并打 debug 日志，不阻断生成（`--prd` 指别处、或用原话重新生成过 PRD 都会走到这里）。文件不存在 → 静默 `[]`；JSON 解析失败或结构不是对象 → `[]` + warn，仍不阻断生成。
- 两类前缀（下游可按前缀过滤）：

| 前缀 | 触发条件 | 示例 |
|---|---|---|
| `[页面]` | 页面小节里未过 `INTER_10` 的条目 | `[页面] 「钱包」未登记，已忽略（可用页名：home/discover/…）`<br>`[页面] 「工作台」为桌面专属模板，不在双端交集白名单（dashboard）内，本次不导入` |
| `[章节]` | 原文缺节（按模板补齐）或正文 < 500 字 | `[章节] 目标用户（已按模板补齐）`<br>`[章节] 原文不足 500 字（已按模板补齐）` |

## PRD 组装规则

`# <产品名>` + 六个**逐字节命中 `validatePRD` 正则**的节标题：`产品概述` / `目标用户` / `核心功能` / `用户流程` / `页面清单` / `非功能性需求`。

- 有原文就用原文（按标题包含匹配取节体，止于下一个同级或更高级标题）；缺节写 `> [假设] 原文未提供本节，已按「<类型>」通用模板补齐。` + 模板兜底。
- **`页面清单` 节一律写规范化页名**（`- home` …），不搬原文条目：原文里的「购物车 / 结算 / 搜索页」在下游 `parsePRD` 里会再丢一次，造成 round-trip 静默掉页。被丢弃的条目同时附在 PRD 页面清单末尾（`> [假设] …`，**不是列表项**，否则会被 `parsePRD` 重新收回页集）并留在假设清单里。
- 标题必须用「用户流程」而不是模板里的「用户交互路径（User Flows）」——`validatePRD` 只认前者，照抄模板标题会制造一条假 warning。
- 产出 PRD 必须 `validatePRD` 的 `errors` 与 `warnings` **双零**（自检场景 39 ③）。

## report 三字段

`generation-report.json` 增：`prdSource`（`'prd'|'doc'`）、`assumptions`（`string[]`）、`prdWarnings`（`validatePRD().warnings` 的机器可读版）。默认原话路径为 `'prd'` / `[]` / 既有 warnings 显性化，产物其余部分不变。

## 已知边界

- 文档里的**页面顺序不被尊重**：入集后仍走 `getPagePriority`（按用户流程频次 + 固定表序），report 里看到的是排序后的页序。
- `## 功能` 小节的内容**不参与** `corePages`，但会被 `parseFeatures` 正常解析（`[P0] …` 之类优先级前缀的语义不变）。
- 未登记的页名不会「猜一个最像的」：要么被别名收敛，要么进假设清单。
- **词表重叠时先走既有页名映射、再走别名**：`通知设置` 会命中既有映射的「设置」→ `settings`（桌面专属 → 记假设丢弃），而不是别名的 `通知 → chat`；`购物车详情` 同理落 `detail`。想强制收敛到某个页，请在文档里直接写该页名（`orders`）。
- 只识别 2–3 级标题下的页面小节；4 空格缩进代码块不被视为围栏（其中 `- 首页` 会被当页面主张）。

## 截图/设计稿（F2-shot）

`templates/design-spec.md` 是**整理模板**，不是新入口：截图 → 模板 → `--from=<design-spec.md>`。

- **只写看得见的**五项：平台（移动端 / PC端）、品牌色（`品牌色：#2f6fed`）、独立页面、主链路流程、功能优先级；推断项行首加 `> [假设]`（**页面节除外**：该节的 `>` 行不参与解析、也不会进假设清单，不确定是不是独立页就写进「核心功能」）。
- **HTML 注释会被自动剥掉**（`--from` 读入后先 `<!-- … -->` 清空再解析）：模板的用法说明留在文件里也不会污染产品类型的关键词计数；同时注释里的内容**不会**进 PRD。**未闭合**的 `<!--`（缺 `-->`）不剥——宁可保留正文也不误删后续章节，此时请自行补全或删掉该行。
- **不写**像素、字号、圆角、间距——第一阶段只取「平台 / 品牌色 / 页集 / 流程 / 功能」，这些数值由 `constants.js` 令牌与模板决定，写了也不会生效。**别承诺「照着截图还原」**：产物是同款骨架 + 对的配色和页集。
- 页面只列**独立页面**（底部 Tab / 侧栏 / 首页入口直达）；弹窗、抽屉、Toast、空态、同一页的步骤态都不算页面。一个页面的多次点击写成**一条流程**，不要拆成多个页面。
- 六节标题不要改（`产品概述`/`目标用户`/`核心功能`/`用户流程`/`页面`/`非功能性需求`）：改了会被当成缺节按模板补齐。
- 品牌色的四个下游消费者：`resolvePrimaryHsl`（配色主色）→ `color-scheme` → 内联 Tailwind 配置 + 降级占位图；自检场景 40 ④ 断言色相真的出现在产物里。
- 平台关键词决定模板集（`移动端/app/手机` vs `PC端/桌面端/管理后台/浏览器`），两端都命中时为 `both`。
